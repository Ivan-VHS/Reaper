# Reaper documentation information architecture

[Project README](../README.md) · [Documentation index](README.md)

This is the canonical navigation map for Reaper. The catalog below is derived from the current repository tree so each maintained Markdown document is discoverable. Source, tests, schemas and build manifests remain authoritative for implementation status.

## Entry points and authority

- **Project entry:** [README](../README.md) — supported language/runtime paths, quick start and limitations.
- **Documentation home:** [docs/README.md](README.md) — core references and topic navigation.
- **Language quick reference:** [LANGUAGE.md](../LANGUAGE.md) — syntax examples and current native subset boundaries.
- **Documentation control:** [DOCUMENTATION_CONTROL.md](DOCUMENTATION_CONTROL.md) — publication and evidence gates.
- **Authority order:** source defines behavior; tests and CI establish what has been exercised; schemas and ABI declarations define interfaces; build files define supported build steps. Documentation must agree with these sources.

## Maintenance contract

- Keep language semantics, compiler status and host/runtime boundaries aligned across README locales, topic hubs, contracts and tests.
- Update this catalog and the relevant topic hub when a page is added, renamed or removed.
- Use canonical DAK URLs for cross-project references; do not use historical repository names for new links.
- Record ABI/schema versions and breaking changes with migration notes.
- Do not present resource quotas as a security sandbox, reference MMIO as live hardware access, or native C17 as complete language parity.
- Verify commands and relative links from a clean checkout before publication.
