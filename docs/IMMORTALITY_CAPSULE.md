# Immortality Capsule — сохранение и восстановление состояния

**Immortality Capsule** — ограниченная подсистема контрольных точек для Python reference runtime языка Reaper. Название сохраняет художественную концепцию исходного псевдокода; техническая реализация оперирует проверяемыми файловыми снимками, а не «бессмертием» процесса или памяти.

## Что реализовано

- **Контрольные точки:** каждый вызов сохранения создаёт новую версию снимка.
- **Атомарная запись:** сначала полностью записывается снимок во временный файл, затем выполняется атомарная замена указателя HEAD.json.
- **Проверка целостности:** SHA-256 вычисляется для канонического представления payload и всего снимка.
- **Восстановление:** если HEAD или выбранный снимок повреждён, загрузчик ищет предыдущую проверенную версию и при необходимости восстанавливает HEAD.
- **Ограниченная история:** по умолчанию хранится не более 16 снимков на капсулу; старые версии удаляются после успешной фиксации новой.
- **Ограничение объёма:** по умолчанию размер полного снимка не может превышать 8 MiB.
- **Изоляция имён:** ID капсул ограничен безопасным набором символов; пути с разделителями, traversal и зарезервированные имена Windows отклоняются.
- **Fail-closed:** если ни одна версия не проходит проверку, загрузка завершается ошибкой, а повреждённые данные не выдаются как восстановленные.

## Подключение в Python

Хранилище включается только явной передачей каталога со стороны приложения-хоста:

```python
from reaper import Interpreter

vm = Interpreter(
    capsule_root=".reaper/capsules",
    max_capsule_bytes=8 * 1024 * 1024,
    max_capsule_snapshots=16,
)

vm.run("""
make checkpoint := capsule_checkpoint("studio-session", {
    "bpm": 93,
    "selected_tracks": [1, 3, 5],
    "active_workspace": "mix"
})
emit capsule_restore("studio-session")
emit capsule_verify("studio-session")
emit capsule_list()
""")
```

Без capsule_root функции капсулы отключены. Это не позволяет программе без разрешения хоста самостоятельно выбирать каталог для записи данных.

## Запуск через CLI и REPL

Хранилище можно разрешить явно при запуске скрипта:

```sh
reaper --capsule-root .reaper/capsules --capsule-max-bytes 8388608 --capsule-snapshots 16 project.rpr
```

Те же параметры применяются к интерактивной сессии:

```sh
reaper --repl --capsule-root .reaper/capsules
```

Если параметр `--capsule-root` не передан, капсула остаётся выключенной. Ограничения CLI: `--capsule-max-bytes` должен быть не меньше 256, `--capsule-snapshots` — не меньше 2.

## Встроенные функции Reaper

| Функция | Аргументы | Результат |
|---|---|---|
| capsule_checkpoint(id, payload) | ID и JSON-совместимое состояние | метаданные созданной версии |
| capsule_save(id, payload) | псевдоним checkpoint | метаданные созданной версии |
| capsule_restore(id) | ID капсулы | payload последней проверенной версии |
| capsule_load(id) | псевдоним restore | payload последней проверенной версии |
| capsule_verify(id) | ID капсулы | статус текущей версии и возможность восстановления |
| capsule_list() | нет | список капсул с проверяемыми снимками |

## Формат и ограничения данных

Payload допускает только JSON-совместимые значения: map с текстовыми ключами, списки, строки, целые и конечные вещественные числа, boolean и null. Циклические ссылки, произвольные Python-объекты, NaN, бесконечности, вложенность свыше 64 уровней и превышение лимита размера отклоняются.

Каталог капсулы содержит неизменяемые файлы snapshot-NNNNNNNN-XXXXXXXX.json и указатель HEAD.json. Если последний снимок повреждён, более ранняя проверенная версия становится текущей восстановленной версией. Если все версии повреждены, система сообщает об ошибке; она не синтезирует потерянные данные.

## Граница безопасности

SHA-256 обнаруживает случайное повреждение и несогласованность данных, но **не является шифрованием или цифровой подписью**. Локальный атакующий, который может менять снимки и их указатель, способен пересчитать хеши. Не храните секреты и ключи в payload. Для защиты от подмены потребуется отдельный HMAC/подписывающий ключ, управляемый доверенным хостом.

Капсула не создаёт бесконечную память, не сбрасывает физическое время, не запускает вечный daemon и не использует shell. Хранилище имеет локальную блокировку в пределах процесса; оно не заявляет распределённую согласованность для одновременной записи из нескольких процессов.

Подсистема относится к Python reference runtime. Native C17 track пока не реализует эту файловую семантику. Lua ReaScripts для Cockos REAPER работают в отдельном хосте и не импортируют Python runtime; эта интеграция не меняет их жизненный цикл и не выполняет файловые операции из audio callback.
