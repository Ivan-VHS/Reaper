# ТЕЗИС — Assertion Provenance Graph for Reaper / МОСТ

**Статус:** реализованный Python-модуль-справочник `reaper.thesis`. Это журнал происхождения утверждений и их проверки, а не автоматический фактчекер, правовая экспертная система или механизм достижения консенсуса.

## Зачем он нужен Reaper

В исходном материале повторялись инженерные проблемы: утверждения без привязки к источникам; цитаты без устойчивых координат; сравнение чисел из разных периодов; смешение наблюдений и предположений; неразрешённые противоречия; исправления, стирающие прежнюю формулировку. ТЕЗИС превращает эти проблемы в типизированные записи.

## Основные сущности

- **Claim (`clm:`):** одно ограниченное утверждение, его область, необязательный временной интервал и необязательная тройка «метрика / значение / единица».
- **Evidence (`evd:`):** связь с утверждением (`supports`, `contradicts`, `contextualizes`), непрозрачная ссылка на источник (`src:`), класс источника, SHA-256 артефакта, локатор и время фиксации.
- **Статус проверки:** `proposed`, `reviewed`, `contested`, `unresolved` или `withdrawn`. Автоматического статуса `verified` намеренно нет.
- **Ревизия:** каждое изменение формулировки добавляется отдельной записью с хешем предыдущего текста, причиной и временем. Прежние доказательства сохраняются для повторной оценки.
- **Ссылка на участника:** необязательный непрозрачный идентификатор `anon:`. Реальные имена и учётные записи не являются полями идентичности.

## API

```python
from reaper.thesis import ThesisLedger

ledger = ThesisLedger()
claim = ledger.add_claim(
    "clm:sample-count",
    "The observed count for this window is 12.",
    "case:sample",
    created_at_utc="2026-11-20T10:00:00Z",
    period_start_utc="2026-11-01T00:00:00Z",
    period_end_utc="2026-11-08T00:00:00Z",
    metric_key="event.count",
    quantity_value=12,
    quantity_unit="events",
)
ledger.add_evidence(
    "evd:archive-a", claim.claim_id,
    relation="supports",
    source_ref="src:archive-a",
    source_kind="document",
    source_class="primary",
    content_sha256="<64 lowercase hex characters>",
    locator="page:4/paragraph:2",
    captured_at_utc="2026-11-20T10:05:00Z",
    actor_ref="anon:reviewer-01",
)
snapshot = ledger.snapshot()
```

Вместо placeholder необходимо передать SHA-256 точного файла-источника. API не скачивает, не аутентифицирует и не ранжирует внешние источники.

## Сравнение и противоречия

`compare_quantitative_claims()` выполняет сравнение только при совпадении области, ключа метрики, единицы измерения и точного временного окна. Результат содержит числовую разницу и проверку допуска, но не выбирает истинное утверждение. Разные периоды, единицы или области считаются несопоставимыми.

Противоречащее свидетельство остаётся прикреплённым к утверждению. Статус меняется только явным вызовом `set_status()`. Добавление свидетельства не меняет его автоматически. После пересмотра формулировки статус возвращается в `proposed`, поскольку предыдущее ревью нужно повторить.

## Приватность и целостность

- Храните непрозрачные ссылки, а не имена, номера аккаунтов или персональные биографии.
- `anon:` и `src:` обозначают псевдонимы, но не доказывают анонимность или подлинность личности.
- SHA-256 связывает запись с байтами; он не доказывает подлинность издателя или истинность источника.
- Необязательный Reaper `AuditLog` сохраняет метаданные событий и дайджесты, но не текст утверждений.
- Хеш снимка — отпечаток содержимого, а не цифровая подпись.
- Имена, политические ярлыки и спорные утверждения из расшифровки не импортируются в модель данных.

## Тесты

`python -m unittest tests.test_thesis -v`

Проверяются сопоставимость областей и периодов, связи источников, непрозрачные идентификаторы, некорректные временные метки и дайджесты, сохранение ревизий, детерминированный экспорт и минимизация аудита.
