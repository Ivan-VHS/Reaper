# REAPER / MOST — архитектура реестра 813 возможностей

**Версия реестра:** 813 предложений (1–147 + 148–813).  
**Статус этого документа:** архитектурная декомпозиция и план приёмки; не означает, что перечисленные функции реализованы.  
**Базовая ветка:** native C17 / semantic IR.  
**Принцип:** REAPER — единственный язык, грамматика, типовая система, память, runtime и backend. МОСТ — точная таблица русских написаний существующих ключевых слов REAPER; отдельные декларации, AST, resolver, runtime или backend не создаются.

## 2. Один язык — две записи

### REAPER — семантическое ядро
- Канонические типы, значения, правила преобразования, области видимости и модель ошибок.
- Однозначная грамматика, независимая от русского падежа, рода, числа и синонимии.
- Явные эффекты, права, владение памятью, потоки исполнения и платформенные возможности.
- Типизированный AST и IR — единственный путь к оптимизации и backend.
- Никакой скрытой аллокации, I/O, сетевого доступа, привилегий или фоновой работы.

### МОСТ — точные русские псевдонимы REAPER
- Русское слово заменяет только уже существующий keyword REAPER.
- После замены поток поступает в существующие REAPER parser, AST, resolver, type/effect checker и Canonical IR.
- Имена функций, переменных и модулей остаются обычными Unicode-идентификаторами REAPER.
- Автоматическое склонение, свободная синонимия, intent inference и отдельные доменные словари не входят в компиляцию.
- Любая возможность, отсутствующая в REAPER, отсутствует и в МОСТ.

### Контракт эквивалентности
Для любого русского фрагмента с поддерживаемыми псевдонимами должны выполняться условия:
1. точная замена русского keyword на соответствующий keyword REAPER;
2. идентичный поток канонических токенов;
3. один и тот же parser и AST;
4. одинаковые типы, эффекты, ошибки и порядок вычислений;
5. тот же Canonical IR и результат исполнения;
6. differential test против исходного REAPER-фрагмента.

## 3. Разделение по слоям реализации

| Слой | Ответственность | Не должен содержать |
|---|---|---|
| Lexer | токены UTF-8, ключевые слова, числа, строки, операторы, source spans | морфологическое угадывание смысла |
| Parser / AST | единая грамматика REAPER для обоих вариантов написания | сетевые/файловые операции |
| Russian alias map | точное отображение русских ключевых слов на REAPER token spellings | морфология, stemming, свободные синонимы и intent inference |
| Name/type checker | области видимости, типы, единицы, полнота match, контракты | неявное приведение опасных значений |
| Effect/capability checker | I/O, сеть, время, секреты, доступ, параллелизм | неявное предоставление полномочий |
| Semantic IR | канонические типизированные операции и source map | русский текст как исполняемая инструкция |
| Optimizer/backend | доказуемо сохраняющие семантику преобразования, native/WASM | оптимизации без fallback и проверки |
| Runtime / stdlib | память, потоки, коллекции, форматы, сеть, безопасность | функциональность, не заявленную контрактом |
| Tooling | тесты, диагностика, форматирование, профилирование, docs | недостоверные заявления о coverage/скорости |
| Host adapters | ОС, браузер, БД, сервисы, плагины | обход capability и sandbox границ |

## 4. Очерёдность внедрения

### M1 — Единый REAPER parser и source mapping
- Разобрать текущий lexer API и закрепить token/source-span контракт.
- Ввести AST для модулей, блоков, объявлений, функций и выражений.
- Добавить Pratt parser для приоритетов арифметики, сравнений и логики.
- Ввести понятные диагностики с исходной строкой/столбцом и тестами отрицательных случаев.
- Сохранить точный синтаксис REAPER; русские псевдонимы нормализовать до существующего token stream.

**Приёмка M1:** C17 build; unit tests на precedence, скобки, source spans, UTF-8 identifiers, malformed input; parser не исполняет код.

### M2 — Семантика REAPER
- Развивать существующий REAPER name resolver, типы, эффекты и контракты.
- Не добавлять в язык отдельную морфологию или словари МОСТ.
- Сохранять единый Canonical IR для всех исходных псевдонимов.
- Добавить differential tests, доказывающие идентичность русских aliases и соответствующих REAPER tokens.

**Приёмка M2:** исходник REAPER и вариант с точными русскими aliases дают одинаковый token stream, IR digest и результат тестового evaluator.

### M3 — Типы и контракты
- Nominal/refinement types, Option/Result, ADT и exhaustive match.
- Размерностные типы времени, длины, частоты, массы и валют.
- Явные overflow/rounding policies; Decimal для денежных контрактов.
- Предусловия/постусловия и проверяемые инварианты.
- Только затем — интервальная арифметика, матрицы, тензоры и символьные выражения.

### M4 — Память, эффекты и конкурентность
- Ownership/borrow/regions и гарантированное освобождение ресурсов.
- Effect rows и capability-gated системные операции.
- Структурированные задачи, отмена, каналы, backpressure, дедлайны.
- Модель памяти и атомарные операции с заданным memory ordering.
- Никаких обещаний lock-free/zero-copy/real-time без платформенных тестов.

### M5 — Данные и безопасность
- Типизированные схемы, миграции, сериализация и bounded parsing.
- Безопасные SQL/HTML/shell контексты через параметризованные API.
- Untrusted input, секреты, audit, rate limits, SSRF/egress policies.
- Транзакционные изменения и явные политики частичного отказа.

### M6 — Инструментарий и интеграции
- Тестовый раннер, property-based и differential tests.
- Debug metadata, трассировка правил, профилирование latency/allocations.
- Типизированная конфигурация, события, клиенты сервисов и host adapters.
- CLI, документация и отчёт о готовности компонента.

## 5. Правила приоритизации 666 новых предложений

Каждое предложение получает:
- **ID** — неизменяемый номер;
- **kind** — syntax / type / compiler / stdlib / runtime / tooling / host;
- **layer** — конкретный владелец;
- **dependencies** — обязательные предшествующие контракты;
- **status** — proposed / specified / implemented / tested / deprecated;
- **target** — portable / native / WASM / browser / OS-specific;
- **effects** — memory, io, network, clock, crypto, process, unsafe;
- **acceptance** — исполняемые positive/negative tests и критерий производительности, если он заявлен.

Похожие пункты объединяются в одну реализацию с несколькими фасадными API, но сохраняют отдельные ID. Например, rate limiting в языке, API-клиенте и event runtime может использовать общий примитив, но каждый сценарий получает собственный контракт и тесты.

## 6. Жёсткие архитектурные решения

1. **Не делать 666 ключевых слов.** Ключевые слова нужны только для устойчивых грамматических конструкций. Большинство возможностей — типы, функции стандартной библиотеки, атрибуты, декларации или инструменты.
2. **Не делать MOST вторым runtime.** MOST — frontend/notation layer, а не отдельная машина исполнения.
3. **Не угадывать русский смысл.** Синонимы и падежи ограничиваются областью словаря; конфликтующие соответствия завершаются диагностикой.
4. **Не обещать статическое доказательство там, где его нет.** Динамические проверки маркируются как runtime checks; эвристики — как warnings.
5. **Не смешивать переносимое ядро с платформенными API.** OS, browser, WASM, SIMD, DMA, audio realtime и crypto получают target/capability gates.
6. **Не добавлять скрытые эффекты.** Часы, случайность, сеть, файлы, секреты, окружение и процессы объявляются явно.
7. **Не удалять Python compatibility oracle до parity.** C17 миграция считается завершённой только после differential conformance и CI на полном наборе поведения.
8. **Не считать каталог реализацией.** Статус implemented разрешён только при наличии кода, тестов и подтверждённого CI.

## 7. Текущая точка проекта

На ветке `feat/most-semantic-ir` имеется C17 lexer foundation и небольшой backend-neutral semantic IR с отдельным структурным verifier. Это фундамент для дальнейшего frontend, но пока не parser, не полноценный type checker и не исполняемый native compiler.

Следующий инженерный шаг — **M1: Parser + AST + Pratt expressions + source spans**. МОСТ не требует отдельного resolver: после токенизации используется существующий REAPER parser и name resolver.
