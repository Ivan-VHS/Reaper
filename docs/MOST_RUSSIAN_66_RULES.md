# МОСТ — 66 правил формирования русского языка программирования

**Редакция:** проект стандарта 0.1.  
**Статус:** все 66 правил сведены в спецификацию; русские ключевые слова распознаются нативным C17-лексером, а Python-эталон исполняет ограниченное подмножество русских конструкций через совместимые токены. Полная грамматика, морфологический разрешатель, типовая система и native/WASM генерация для русского фронтенда пока не заявляются как готовые.

МОСТ — русскоязычный исходный язык в составе REAPER. Русский — основной язык ключевых слов, стандартных имён, документации и диагностик. Совместимый синтаксис REAPER сохраняется. Оба фронтенда должны понижаться в одну типизированную модель и один проверяемый Canonical IR; отдельного runtime для МОСТ не будет.

## 1. Нормативные принципы

1. МОСТ разбирает формальную грамматику, а не произвольную человеческую речь.
2. Синонимы, падежные формы и доменные термины разрешаются только явными таблицами в текущей области видимости.
3. Неизвестное или неоднозначное имя вызывает диагностическую ошибку; компилятор не угадывает смысл.
4. Морфология не меняет тип, overload, эффекты, права, порядок вычислений или поведение программы.
5. Каждый исходный фрагмент сохраняет source map: исходную форму, координаты, канонический символ и путь до IR.
6. Произношение, ударение, тембр, эмоции и голосовой ввод не являются частью семантики исходного файла.
7. Возможности получают статус implemented только при наличии исполняемого кода, тестов и CI.

## 2. Целевая русская запись

~~~most
модуль счётчик

структура Состояние {
    значение: целое32 = 0
}

функция увеличить(значение: целое32, шаг: целое32) -> целое32 {
    вернуть значение +| шаг
}

пусть шаг: целое32 = 2
переменная итог: целое32 = увеличить(40, шаг)

если итог > 0 {
    вывести "готово"
} иначе {
    вывести "пусто"
}
~~~

Это проектная форма синтаксиса, а не утверждение, что пример уже полностью исполняется. Сейчас нативный лексер распознаёт русские зарезервированные слова; parser объявлений, resolver, checker и runtime для МОСТ остаются отдельными этапами.

### 2.1 Русская лексика ядра

| Назначение | Канонические ключевые слова |
|---|---|
| Модуль и доступ | модуль, импорт, как, публичный, экспорт |
| Объявления | функция, структура, перечисление, типаж, реализация, тип, константа |
| Привязки | пусть, переменная, изменить |
| Управление | вернуть, если, иначе, выбор, для, в, пока, прервать, продолжить, отложить |
| Память и ресурсы | область, сырой, арена, уничтожить |
| Задачи и реактивность | сигнал, асинхронно, ожидать |
| Проверки и контракты | тест, вычислить_при_сборке, требует, гарантирует |
| Системная граница | небезопасно, внешний, где |
| Значения и логика | истина, ложь, ничего, и, или, не |
| Взаимодействие | вывести, сказать, спросить |

Предметные имена остаются Unicode-идентификаторами: счётчик, состояние, результат, файл. Предлагаемые типы целое8/16/32/64, вещественное32/64, логический, строка, массив<T>, срез<T>, ссылка<T> и результат<T, Ошибка относятся к типовому реестру, а не к управляющим ключевым словам.

### 2.2 Привязки и изменение

- пусть имя: Тип = выражение — неизменяемая привязка.
- переменная имя: Тип = выражение — изменяемая привязка.
- изменить имя := выражение — явное изменение.
- функция имя(параметры) -> Тип — функция с явной сигнатурой.
- вернуть выражение — явный результат.

Существующие операторы ядра сохраняют одну семантику: :=, ::, ??, +%, +|, ->, ==, !=, <=, >= и **. Язык интерфейса не меняет правила арифметики, переполнения, приоритетов и ошибок.

## 4. Морфология и словари

Разрешатель работает после лексического выделения идентификаторов и до проверки типов. Целевой алгоритм: проверить корректность UTF-8; нормализовать форму к NFC; искать точную запись в словаре модуля и импортов; получить один канонический символ; сохранить source map. Ноль совпадений — неизвестное имя. Несколько совпадений — ошибка неоднозначности с квалифицированными вариантами.

Склонения регистрируются явно: например, файл, файла, файлу, файлом, файле могут быть связаны с одним символом std::файл. Это описание целевого механизма, а не синтаксис готового resolver. Автоматическое угадывание основы и произвольное образование форм в ядро не включаются.

Синонимы регистрируются явно. Предпочтительное отображаемое имя может зависеть от профиля проекта, но символ, ABI, тип и поведение неизменны. Коллизии aliases запрещены.

## 5. Письменность и речь

Исходник — Unicode-текст. Регистр, NFC, допустимые символы, визуально сходные знаки и координаты Unicode должны закрепляться conformance-тестами. Ударение, интонация, тембр, эмоция, паузы и тон голоса не являются машинной семантикой. Голосовой ввод и ASR/TTS — отдельные инструменты: распознанный текст показывается пользователю; неоднозначность требует подтверждения до компиляции.

## 6. Совместимость и развитие

Русский и совместимый REAPER-фронтенды должны получать одинаковые типы, эффекты, порядок вычислений, ошибки и IR. Импорт словаря не меняет грамматику всего файла. Новые формы версионируются; устаревшие получают срок совместимости, предупреждение и инструмент миграции. Локаль ОС не меняет смысл программы.
