# Reaper Aesthetic & Architecture Evolution Framework

The RAAEF framework family is documented in [frameworks/aesthetic/README.md](../frameworks/aesthetic/README.md). Its canonical public entry point is frameworks/aesthetic/all.rpr; discovery metadata is centralized in frameworks/catalog.v1.json.

RAAEF provides nominal tagged profile contracts, aesthetic HIR/MIR/LIR passes, a Reaper reference-runtime compiler adapter, current-versus-proposed architecture graph validation and comparison, dependency-edge consistency and cycle checks, design quality assessment, and bounded architecture/design/source change planning. Observe returns assessments and architecture deltas without creating a patch plan; propose emits a bounded plan after PLAGUE policy approval and risk/benefit gates.

The Reaper C17 core now has a shared typed HIR/MIR/LIR API for a bounded scalar expression set and aesthetic property nodes, plus a deterministic C17 instruction-table emitter. The existing native C17 expression parser now feeds typed HIR for a bounded expression subset: i64 and finite decimal literals, decoded strings (including empty strings), booleans, unary +/- over i64/f64 and binary + - * / over matching i64 or matching f64 operands. Mixed numeric arithmetic is rejected rather than implicitly promoted. Decimal parsing is independent of host numeric locale. Source names and line/column positions are preserved. Identifiers, null, non-i64 arithmetic, imported .rpr modules, functions/calls, collections, control flow, effects and native runtime calls remain outside this frontend. RAAEF's Reaper modules are therefore not yet natively compiled as a complete package and the declarative LIR does not call a native renderer.

See [Native typed compiler IR](NATIVE_IR_EXECUTION.md) for exact v1 node coverage and [Native evolution apply engine](REAPER_AUTONOMOUS_EVOLUTION.md) for the guarded workspace/branch transaction contract.

SOMO consults the PLAGUE v1 action-policy module before planning: observation requires read/analysis/report actions, and proposal mode additionally requires the declared plan capability. This is policy integration, not an authenticated repository grant or path-level authorization system.

The C17 core also now exposes an SHA-256-pinned whole-file patch descriptor and a capability-gated transactional apply engine contract. The signed grant is bound to a canonical digest of the requested patch set, and expiry/revocation checks use time returned by the trusted host clock rather than guest-supplied time: grant validation, path scopes, isolated workspace, staged file snapshots, sandboxed registered checks, atomic topic-branch publication, durable audit and rollback/recovery callbacks are mandatory. The engine is callback-only and has no ambient host authority. However, concrete Windows/POSIX Git workspace and sandbox adapters and a Reaper-to-native binding are not yet implemented or verified against a real repository. SOMO therefore keeps apply blocked. No main-branch writes, merges or releases are performed by this framework foundation.
